远程主机 CPU 为 Intel Xeon Platinum 8368，系统可见 152 个逻辑 CPU 和约 1 TiB RAM；PyTorch CPU 后端显示 AVX512，CPU 不支持 AVX512-BF16。长文本脚本因此使用 FP32、32 个 intra-op 线程和 4 个 inter-op 线程，并通过 `CUDA_VISIBLE_DEVICES=` 禁用 CUDA。

| 若叶睦 | 55.2 秒 | 24.88 秒 | 2.22 |

这是 32 线程 FP32 推理的墙钟吞吐：合计约每 1 秒生成音频需要 2.17 秒推理时间，或每秒推理时间生成 0.46 秒音频。模型加载约 1.7 秒，未计入上述单段耗时。该值是这台共享 CPU 上这两段文本的一次实测，不是 CPU 核秒数，也不直接代表其他长度或机器。

### RVC CPU 转换实测

短句基线使用固定的短句源音频。输入时长 2.56 秒；RVC 输出 2.54 秒，40 kHz 单声道。特征提取、基频、合成分别用时 0.15、1.61、1.22 秒，合计约 2.98 秒，约需 1.17 秒推理时间转换出 1 秒音频。

### RVC 声音偏冲的排查与参数对照

原 RVC 短句/长台词的 RMS 分别为 -16.90/-15.00 dBFS；对应 Qwen 输入为 -21.59/-23.36 dBFS。原 RVC 峰值约 -2 dBFS，但 PCM 文件中没有达到满刻度的削波样本。因此更像是输出平均响度明显偏高，再叠加 RVC 音色转换的粗糙感；波形指标不能排除主观听感上的刺耳或失真。

### Pitch 差分与 F0 参考测量

RVC 的 `pitch` 是对输入基频的整体半音移调，不是“设定成目标角色的固定音高”；官方 CLI 也将其定义为 semitone shift。[RVC CLI 文档](https://github.com/RVC-Project/Retrieval-based-Voice-Conversion-WebUI/blob/main/docs/en/cli.md) 若要从输入估一个起始值，先对输入与目标参考提取有声段 F0 中位数，再计算 `12 × log2(F0_target / F0_input)`，取最接近的整数半音，试听时再比较前后约 2 个半音。

这次用 Praat autocorrelation（10 ms 步长、F0 范围 60–500 Hz）测得：

| 音频 | F0 p10 / p25 / 中位数 / p75 / p90 | 说明 |
| --- | --- | --- |
| 《离骚》原始朗读 | 100 / 109 / **133** / 164 / 186 Hz | 用户低男声音源，39.17 秒 |
| 《离骚》RVC `pitch=+16` | 250 / 270 / **319** / 402 / 441 Hz | 39.16 秒；实际 F0 分布较宽 |
| 当前平静风格汉堡参考 | 222 / 239 / **265** / 285 / 305 Hz | 用户认可的“无口”RVC 输出 |
| 汉堡参考的 Qwen 输入 | 224 / 240 / **265** / 284 / 304 Hz | 与 RVC 后几乎相同，说明此参考主要保留了源 TTS 的 F0，不是独立的原作人声测量 |

按这条“平静风格汉堡参考”的中位数做粗略匹配，《离骚》输入的中位移调约 **+12 半音**。`+16` 输出中位数为 319 Hz，比该代理参考高约 3.2 半音；此前用户觉得《离骚》`+16` 听感接近，是这条朗读上的主观选择，不应直接推广为所有低音源的通用值。参考本身来自 Qwen→RVC，而不是干净的官方睦原声，因此 265 Hz 只是项目内的工作参照，不能称为“若叶睦官方频率”。官方角色简介描述睦寡言、情绪不外露，但没有公布数值 F0。[官方角色简介](https://anime.bang-dream.com/avemujica/character/mutsumi/)

用户确认这组近似估值可作为当前经验记录：对低声源先以 +12 左右做平静语气候选；《离骚》的 +16 继续保留为该文本的高能试听选择。

本地一分钟《若叶睦锯木头》视频在未做人声分离时测得中位数约 416 Hz，可能混入音效或音乐，暂不用于平静语音标定。使用 [`analyze_voice_f0.py`](../scripts/analyze_voice_f0.py) 可重复测量：

```bash

```

该估算只用于生成 pitch 候选；语速、情绪、音节内容、RVC 模型训练音域和 F0 算法都会影响结果。做平静声线和高能喊话时，应各自留一条参考分布，不要只靠一个全局中位数。

## 历史 Qwen A100 实测吞吐（已弃用）

2026-11-15 在 `a100-whn` 的 NVIDIA A100-SXM4-80GB 上实测，模型加载后测了 3 次同一句话生成；各次生成长度会随采样变化。

| 次数 | 推理用时 | 生成音频时长 | 音频秒 / 推理秒 |
| --- | ---: | ---: | ---: |
| 1 | 5.431 秒 | 4.160 秒 | 0.766 |
| 2 | 5.652 秒 | 4.320 秒 | 0.764 |
| 3 | 4.405 秒 | 3.360 秒 | 0.763 |
| 合计 | 15.488 秒 | 11.840 秒 | 0.764 |

这组数据对应约 **1.31 个 A100 推理秒/生成音频秒**，即每用 1 秒推理时间生成约 0.76 秒音频。按这个样本的吞吐粗略折算，生成 1 分钟音频约需 79 秒模型推理时间；模型首次加载另约 3.2 秒。一次独立首轮推理会受初始化和共享 GPU 负载影响，曾测得 6.03 秒生成 4.08 秒音频，所以实际速度会浮动。

PyTorch allocator 在一次测量中报告已加载模型约 3.89 GiB、推理峰值约 4.02 GiB；这是本进程的 PyTorch 分配量，不等于整张卡的 `nvidia-smi` 显存占用。测试时 GPU 上有其他任务，结果反映共享卡上的一次实际吞吐。没有做算子级 FLOPs profiling，因此这里报告的是可复现的 A100 吞吐率，不把它换算成 TFLOPS。

## 复现配置

### CPU-only RVC 音色转换

```bash
cd /data3/whn/Project-voca/frameworks/RVC
PYTHONPATH=/data3/whn/Project-voca/frameworks/RVC:/data3/whn/Project-voca/.venv-qwen/lib/python3.10/site-packages:/data3/whn/Project-voca/.venv-rvc-cpu/lib/python3.10/site-packages \
rmvpe_root=/data3/whn/Project-voca/assets/rvc \
CUDA_VISIBLE_DEVICES= OMP_NUM_THREADS=32 MKL_NUM_THREADS=32 OPENBLAS_NUM_THREADS=1 RVC_AUDIO_FORCE_CPU=1 \
/data3/whn/Project-voca/.venv-rvc-cpu/bin/python infer/cli.py \
  --model /data3/whn/Project-voca/models/rvc/mutsumi-rvc/mutsumi.pth \
  --input /data3/whn/Project-voca/outputs/若叶睦_你好一二三为什么.wav \
  --output /data3/whn/Project-voca/outputs/若叶睦_RVC_你好一二三为什么_柔和.wav \
  --index /data3/whn/Project-voca/models/rvc/mutsumi-rvc/added_IVF345_Flat_nprobe_1_mutsumi_v2.index \
  --index-rate 0.45 --rms-mix-rate 0.45 --protect 0.45 \
  --pitch 0 --f0-method rmvpe --overwrite
```

该命令隐藏 CUDA，只跑 CPU。远程输出仍位于 `outputs/若叶睦_RVC_你好一二三为什么_柔和.wav`、`outputs/若叶睦_RVC_汉堡独白_柔和.wav`；本地副本已归档在 `outputs/archieve/202611052130/`。

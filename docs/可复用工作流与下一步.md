# 可复用工作流与下一步

本页说明已封装的入口、工作区边界和下一批值得做的功能。项目仍把 Qwen、RVC、GPT-SoVITS 放在各自的 CPU 环境中运行；统一的是参数、命令和输出记录，不是它们的 Python 依赖。

## 当前整理结果

| 功能 | 入口 | 用途 |
| --- | --- | --- |
| 项目配置与环境检查 | `voca init-config`、`voca doctor`、`voca env snapshot` | 建立本机私有配置；检查命令与远程 CPU 环境；保存隔离环境的 pip 版本清单 |
| 命名音色配方 | `voca profiles`、`voca synth` | 复用无口、日常 RVC、抽泣 GSV、激动 GSV 四套配方，支持常用参数临时覆盖 |
| 参数扫描 | `voca sweep` | 复用太阳宣言的 Qwen→RVC 参数扫描，可只跑选定变体或只生成源音频；默认不覆盖 |
| 成品信息记录 | `voca manifest`、合成后的自动 sidecar | 写入 SHA-256、音频/视频流信息、配方和参数，便于追溯源文件和复刻条件 |
| 素材索引与质检 | `voca index-assets`、`voca qc` | 建本地音视频清单；查看时长、编码、采样率、声道、画幅及平均/峰值响度 |
| 试听与归档 | `voca compare`、`voca archive` | 生成本地 A/B 播放页；归档命令默认只预演，确认路径后加 `--apply` 才移动文件 |
| 小剧场与视频 | `voca scene`、`voca video` | 按 JSON 逐句选择音色、插入停顿、拼接旁白；静态图或动态视频都能作为字幕背景 |

所有模型调用默认在 `a100-whn` 的 CPU 环境执行，命令会显式隐藏 CUDA。`voca synth` 把本次文本临时送到远端合成，命令结束后清理远端临时目录，再把 WAV 拉回指定的本地路径。

## 安装与第一次检查

需要 Python 3.9 或更新版本。在项目根目录运行：

```bash
python3 -m pip install -e '.[video]'
voca init-config
```

这会安装轻量本地命令和字幕渲染需要的 Pillow；FFmpeg/ffprobe 需单独安装并放入 `PATH`。`config/local.toml` 已加入 `.gitignore`，第一次建立后检查 `[remote]` 中的主机名、项目根目录和 Python 版本。

`voca env snapshot` 会记录本地及三套远程隔离环境的解释器版本和 `pip freeze` 清单，快照写入 Git 忽略目录 `outputs/manifests/`。

```bash
voca doctor
voca doctor --remote
voca profiles
voca env snapshot
voca scene validate configs/scenes/example_scene.json
```

不想安装命令入口时，可以把 `voca` 换成 `python3 -m voca`。从项目目录以外运行时，传入 `--config /path/to/config/local.toml`。

## 合成与配方

音色配方的权重路径、路由和默认参数集中在 `configs/voice_profiles.toml`。常用生成示例：

```bash
voca synth --profile mutsumi_daily_rvc \
  --text-file scripts/你的私有朗读稿.txt \
  --output outputs/试听试验/日常试听.wav

voca synth --profile mutsumi_excited_gsv \
  --text-file scripts/你的私有朗读稿.txt \
  --output outputs/试听试验/激动试听.wav
```

RVC 配方可以临时覆盖 `--index-rate`、`--pitch`、`--protect` 和 `--rms-mix-rate`；GSV 配方可以覆盖 `--top-k`、`--top-p`、`--temperature`、`--speed` 和 `--target-rms-dbfs`。所有成品语音默认应用 `[audio].output_gain = 3.0`（约 +9.54 dB），并将峰值限制在 -1 dBFS；单次可用 `--output-gain` 覆盖。生成文件旁的记录写到 `outputs/manifests/`。默认不覆盖已有文件；明确要替换时加 `--overwrite`。

选定基线的音频文件、生成台词、训练音频、参考转写、权重、框架和 Python 虚拟环境都是本机/远程工作区素材，不会提交到公开 GitHub 仓库。文案、参考音频和训练数据在远端只用于本次模型调用或既有训练；项目本身不把它们复制进版本库。

## 一轮试听怎么走

```bash
voca qc outputs/试听试验/候选.wav
voca compare outputs/基线/你的基线.wav outputs/试听试验/候选.wav
voca manifest outputs/试听试验/候选.wav --profile mutsumi_daily_rvc
voca index-assets
```

`compare` 生成 `outputs/compare/listen.html`，用浏览器打开即可逐条试听。`qc` 提供编码和响度的客观信息，不评价音色相似度、哭腔或表演是否自然；最终听感仍应人工比较。`index-assets` 默认递归扫描项目媒体并将清单写到本机忽略目录。

不需要的试听先预演归档目标：

```bash
voca archive outputs/试听试验/候选.wav
voca archive outputs/试听试验/候选.wav --apply
```

第二条会把文件移动到 `outputs/archieve/日期_cli/试听试验/`。归档保留文件，不执行永久删除。

## 小剧场和动态背景

修改 `configs/scenes/example_scene.json` 的 `title`、台词和 `pause_after_ms`，每句引用 `profiles` 中的键。然后只生成音频：

```bash
voca scene validate configs/scenes/example_scene.json
voca scene render configs/scenes/example_scene.json
```

也可以加背景视频或静态图，一次生成带字幕 MP4：

```bash
voca scene render configs/scenes/example_scene.json \
  --background-video 视频音频下载/短视频背景素材/背景.mp4
```

直接给已有旁白加字幕时使用 `voca video --background-video ...`，或用 `--image` 指定静态背景。文本需与音频逐字一致；字幕用远端 MMS_FA CPU 强制对齐。动态背景会循环到旁白结束，按背景画面比例缩放并叠加字幕。视频需本机 FFmpeg、Pillow、中文字体和可用的 `a100-whn` SSH 连接。

目前小剧场按行调用配置的推理脚本；每行会重新加载相应模型，跨很多句时速度会受启动和加载影响。先用短场景确定台词顺序、停顿和声线，再做长片段更省时间。

## 输出与归档约定

- `outputs/基线/`：用户明确命名并确认的风格样本；原始 GSV 激动基线保持为 GSV 输出，不自动接 RVC 或响度匹配。
- `outputs/试听试验/`：当前轮试听。满意后先更新基线复刻记录，不覆盖已确认样本。
- `outputs/archieve/`：被替代的试听、训练中间件和旧实验；拼写 `archieve` 沿用现有目录。
- `outputs/manifests/`、`outputs/compare/`、视频、音频、素材、模型和依赖环境：本机生成或保存，全部由 `.gitignore` 排除。
- `scripts/*.txt`：朗读稿/测试文案默认保持本地；依赖清单 `scripts/requirements-subtitles.txt` 除外。

## 下一步功能建议

1. **批量合成进程**：按音色把多句台词成组提交，在一次进程里复用已加载的 GSV/RVC 模型；同时输出按行时间轴和逐句 wav。对多角色小剧场提升最大，先做这一项。
2. **角色与表演分层**：一个场景行分别声明“角色音色”和“表演处理”，把 RVC 音色转换、GSV 参考情绪、语速/停顿和后期响度拆开；这样同一台词可复用角色但换情绪。
3. **素材片段台账**：给 few-shot/训练片段记录起止时间、转写文件、采样率、噪声/削波标注和来源指针，合成前检查参考音频与转写是否成对。
4. **参数实验表**：对 profile 的少数旋钮生成小规模、可复现矩阵，自动命名样本、生成试听页并写入 manifest；不要默认穷举所有参数组合。
5. **人工字幕修订回路**：把强制对齐的低置信字、句首/句尾截断和时间重叠汇总成校对表，再导入修订后的 SRT 复渲染。
6. **可选轻量后期链**：已有全局增益和峰值限制。后续可增加去直流、轻度降噪等独立开关，并保留原始生成音频；不会覆盖已选定的 GSV 原声基线。

建议顺序：先做批量合成和逐句清单，再做素材台账，然后按实际制作痛点增加参数矩阵和字幕修订。GUI 或容器化目前优先级低于这几项，因为现有 CLI 已覆盖主要步骤，真正耗时点是反复加载模型和素材管理。
